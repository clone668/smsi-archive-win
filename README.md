# SMSI Windows 归档同步客户端

这是一个只读的 Windows 桌面客户端。它只连接 Ubuntu 的 SSH，不连接 Google Drive，也不执行远端删除。

数据方向：

```text
Ubuntu /data/smsi-archive -> Windows 本地归档目录
```

## 启动测试

在 Windows 上双击 `启动客户端.cmd`。脚本第一次运行会创建 `.venv` 并安装依赖，之后使用 `pythonw.exe` 启动，不会显示黑色控制台。程序初次启动窗口居中且不会最大化。

当前版本不编译 exe，代码入口是 `main.py`。

程序使用顶部“归档同步 / 设置”页签，文件列表是默认页面。启动后也会显示在 Windows 系统托盘；点击窗口右上角关闭按钮只会隐藏窗口，后台同步不会被打断。双击托盘图标可重新打开窗口，托盘菜单可以开启或停止自动同步、显示或隐藏悬浮窗，以及退出客户端。

自动同步每 15 分钟检查一次 Ubuntu，只处理最近 7 天新增并已经通过 Ubuntu 完整验证的归档；历史补档由用户在列表中选择后手动同步。稳定历史日期先核对小型验证凭据，摘要未变化时复用缓存，变化时才重新读取 manifest。停止同步会关闭自动模式，并安全取消当前传输；未完成文件会保留在 `.partial` 中，方便下次继续。悬浮窗是一个可拖动的小状态块，显示百分比和速度，双击可打开主窗口。

手动执行完整校验时，Parquet 中的 UTC 时间字段需要时区数据库。启动脚本会检查 `tzdata`，缺少时自动按 `requirements.txt` 安装。

启动时会先显示窗口，再后台读取本地缓存并扫描 Ubuntu。归档日期下的文件节点会在展开日期时加载，避免大量归档对象阻塞界面。

日期列表的“内容”列来自 manifest，优先显示业务表数量和业务记录数；归档总行数仍在详情中显示。悬停或双击日期可以查看对象分类、批次、时间覆盖及各层验证信息；客户端不会为了生成摘要扫描 Parquet。

## 首次设置

1. 打开“设置”。
2. 填写 Ubuntu 地址、SSH 用户名和 SSH 密码。
3. 点击“测试连接”。首次连接会显示 Ubuntu 主机指纹；只有与服务器上确认过的指纹一致时才保存。
4. 选择 Windows 本地归档目录，必要时调整“磁盘保留空间”。
5. 保存设置。

SSH 密码使用 Windows DPAPI 加密保存，不会以明文写入配置文件。主机指纹仍然必须确认。

远端根目录固定为 `/data/smsi-archive`，客户端会自动发现其中所有 `collector=*`，不需要逐个添加采集服务器。

## 同步规则

- 只有 Ubuntu 已完成归档、发布 manifest 并写入验证凭据的日期才允许同步。
- 归档数据通过 SSH 连续字节流传输，目录和 manifest 通过 SFTP 只读访问，避免 SFTP 小请求限制局域网吞吐。
- 文件先写入 `.partial`；每个文件下载后立即核对大小和 SHA-256，全部完成后再次确认 Ubuntu manifest 未变化、Ubuntu 验证凭据有效，才发布正式目录。
- 普通和自动同步使用上述传输校验，避免在 Windows 端重复 Ubuntu 已完成的逐行业务审计。
- 手动“校验选中”会执行完整深度审计，包括 SHA-256、Parquet schema、行数和 business 逐行内容摘要。
- 断网或取消后，未完成文件会保留用于继续下载，但不会被当作已验证数据。
- 每个归档日在下载第一个字节之前先核对空间。正式副本和 `.partial` 临时文件在同一个归档盘上，发布只是同盘改名，所以一次同步需要的空间就是这一天还没下载的部分，加上“磁盘保留空间”（默认 10 GiB，可设 1 至 1024 GiB）。空间不够时这一天会被直接拒绝并说明还差多少，而不是传到一半把盘写满——那种失败只发生在上百个文件里的某一个内部，事后很难判断断在哪里。如果客户端自己的隔离目录还占着空间，消息里会给出占用量和路径，删不删由用户决定。
- 顶部摘要栏常显“归档盘可用”，低于保留值时变红，鼠标悬停可看到总容量和保留下限。
- Ubuntu manifest 发生变化时默认不会自动覆盖 Windows 已有结果；唯一例外是带严格维护证明的“移除旧运行报告”变更，客户端会删除对应旧报告并更新清单和验证凭据，不重新下载业务文件。
- Ubuntu 或 Windows 文件都不会被客户端自动删除。

## 告警通知

这台机器保存归档链条的最后一份副本，同时也是最没人盯着的一份：窗口平时最小化在托盘里，画在界面上的失败没有人会看见。在“设置 → 告警通知”里填写 Telegram 机器人令牌和会话 ID 并开启后，客户端会主动把问题推送出来，触发条件有四个：达到所选级别（默认“警告及以上”）的事件，每条只推一次；自动同步已开启却连续若干小时没有成功扫描 Ubuntu（默认 6 小时，可设 1 至 168 小时）；Ubuntu 已验证副本的最新归档日滞后超过若干天（默认 3 天，可设 2 至 14 天）；本地归档盘可用空间低于“磁盘保留空间”，或者归档目录整个读不到。后三条属于状态告警，报警和恢复各只发一条，不会反复刷屏。“没有成功扫描”这条只在自动同步开启时判断——关掉自动同步后每次扫描都由用户决定，安静是选择而不是故障，此时已有的告警状态会被静默清除，不会谎报一次没发生过的恢复。“数据源停更”只在本机扫描结果还新鲜时判断，否则这种情况会被算作“扫描中断”，避免用自己的失明去指责上游。

归档盘这一条不需要“扫描是否新鲜”的前提，因为它读的是本机磁盘，任何时候都是当前值。它也是唯一在故障发生之前就能报出来的问题：低于保留值时客户端只会拒绝同步，盘上其实还有空间，此时通知还来得及处理。“读不到”和“快满了”分开报告——读不到通常意味着归档盘掉线或被拔掉，比快满严重得多，绝不能被算成“空间充足”。

自动同步每 15 分钟重试一次，同一个故障会被反复记录，因此同一条失败在一小时内只推送一次，其间的重复次数会累计到下一条消息里（例如“操作失败（期间重复 12 次）”）。断网一下午只会得到几条消息而不是几十条——一个会把一次故障讲一百遍的通道，用户只会把它关掉。

告警在独立线程上每两分钟检查一次，不使用界面定时器，因此窗口正忙或卡住时告警照样发得出去；它只读写本地状态库、配置文件和网络，不参与下载与校验，发送失败只会在下一轮重试，绝不会让一次同步或校验失败。第一次开启只记录“从现在开始算新事件”，不会补发历史。发送失败的原因会显示在设置页的提示行里，并在事件列表中按原因记一条信息级记录（同一原因只记一次）——通道本身坏掉时没法用它通知自己，所以这类失败只在本机留痕。消息使用纯文本并在过长时截断，标题里带本机主机名，因为 Ubuntu 备份客户端通常推送到同一个会话，不说明是谁在讲话的消息没有意义。令牌用 Windows DPAPI 加密保存在本机配置里，设置页不回显，留空表示不修改已保存的令牌；“发送测试消息”只验证通道是否连通，不会改变推送进度。

## 本地状态

配置、扫描缓存、SQLite 状态库和日志位于 `%LOCALAPPDATA%\SMSIArchiveSync`，不需要手工编辑。
